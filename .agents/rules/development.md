# Development

1. Inspect `git status`, relevant files and existing conventions before editing.
2. State the intended behavior and keep the change within the requested scope.
3. Implement one small capability at a time; avoid speculative infrastructure.
4. Validate real configuration, update relevant documentation and inspect the diff.
5. Commit related files together; report validation and any remaining limitations.

Do not overwrite user changes, fabricate results or introduce empty success checks.
Keep placeholders visibly marked until their subsystem is implemented.
