# Security policy

Do not post credentials, private inventories or sensitive server information in
public issues, logs or pull requests. Use sanitized examples.

For vulnerabilities, use the repository Security tab's private vulnerability
reporting if it is enabled. Otherwise contact the repository owner privately
through a contact method on their profile; do not open a public issue containing
exploit details or secrets. This learning project has no response-time guarantee.

If credentials are committed, revoke or rotate them immediately and notify the
owner privately. Removing the file does not remove the secret from Git history.
Coordinate history cleanup after rotation. Gitleaks is a preventive check and
does not prove that all secrets have been found.
